# حزمة إصلاح IslamicAI — الدفعة الأولى

## التركيب

فُكّ محتوى الحزمة داخل **جذر** `islamicai-project` بحيث يصير عندك:

```
islamicai-project/
├── tools/          ← سكربتات PowerShell
├── patch/          ← ملفات بايثون الجديدة
├── packages/  apps/  alembic/  ...
└── pyproject.toml
```

## التشغيل

```powershell
cd D:\...\islamicai-project

# 1) عاين أولاً — لا يُكتب أي شيء
.\tools\RUN-ALL.ps1 -DryRun

# 2) نفّذ (يأخذ نسخة احتياطية تلقائياً)
.\tools\RUN-ALL.ps1

# 3) عند الجاهزية، طبّق هجرة القاعدة
.\tools\05-migrations.ps1 -Apply
```

إن منع ويندوز التشغيل:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

## أهم إصلاحين

**1. المطبّع كان يفشل في أبسط حالة عربية.** قبل: `إسماعيل` لا يطابق `اسماعيل`، و`صلاة` لا تطابق `صلاه`. بعد: كلها تتطابق، مع تغطية العلامات القرآنية والأرقام العربية-الهندية والحروف الفارسية.

**2. حُفظ ربط الاستشهاد بموضعه.** المطبّع الجديد يرجّع خريطة إزاحة، فتبحث في النص المطبّع وتسترجع المقطع الأصلي بتشكيله كاملاً:

```python
res = canonicalize(raw)
i = res.canonical.find(search_form_text("بالنيات"))
res.raw_excerpt(i, i + 7)     # -> 'بِالنِّيَّات'
```

بدون هذه الخريطة كان الربط بين نتيجة البحث و`bbox` على الصفحة ينكسر نهائياً.

## ما لم تعالجه هذه الدفعة

- `fts.py` و`fuzzy.py` ما زالا يقرآن من عمود `text` القديم، فالفهارس الجديدة لن تُستعمل حتى تُربط. **لن ترى تحسّن سرعة قبل الدفعة الثانية.**
- `EmbeddingBuilder` ما زال hashing وهمياً بـ 256 بُعد.
- دمج الدرجات ما زال جمعاً خاماً بدل RRF.
- لا Golden Dataset ولا منصة قياس بعد.
- لا OCR، ولا فصل تخطيط (كل عنصر `element_type="text"`).
